请分析提供的漫画参考图，将其反推为 ComfyUI-MOSS-MangaLayout（MOSS 漫画版式控制节点）可以导入、编辑和复用的自定义版式 JSON。

本规则约束参考图反推的版式阶段；用户另行要求内容提示词、工作流或实际采样时，按对应数据契约及执行流程追加交付。用户明确的目标、身份、颜色和尺寸要求优先。

目标：提取实际分格、主体区域、局部／道具区域、字区、跨格主体、读序和遮挡层级，并为整页及每个框写好画面描述。版式用于后续更换人物和剧情。

最终交付的是节点版式库使用的几何版式对象；准确画面内容和台词可在后续通过 LLM 或节点直接提示词模式补充。

一、先区分三种格式

本次使用“版式库 JSON”格式，根对象包含 id、label、description、readingOrder、canvas、promptMode、panels。

panels 是一个有序分格数组，横版、竖版和正方形都使用这个字段。

summary／items 是后续用于生图的内容提示词格式；nodes／links 是完整 ComfyUI 工作流格式。本次交付保持为版式库对象。

二、分析参考图

1. 识别实际分格外框、格间留白、画格大小、相对位置和轮廓。先记录外框四角与相邻边界，再安排格内区域；明显斜边、梯形或其他凸四边形分格按第十节填写 shapes.F。
2. 区分独立分格、嵌入小格、格内局部和跨格前景主体。每个独立画格对应一个 panels 条目；脸、手、气泡或装饰本身属于格内内容。
3. 识别阅读路径，将阅读顺序与前后遮挡分别记录。先后动作使用不同画格；同时发生的局部补充可以采用嵌入格。
4. 按实际需要安排环境、主体、局部、道具和文字区域，区域数量与画面内容匹配。
5. 人物按整页首次出场顺序使用“角色1、角色2、角色3”等稳定编号，同一角色跨格保持编号，便于复用。左右、前后、画内或画外作为独立的位置说明，例如“角色1位于画面右侧”“角色2在门外说话”；位置或镜头改变时仍沿用原编号。角色编号与格号、槽位编号分别管理，S_2 不自动对应角色2。动物另用“黑猫1”等稳定称呼，物件使用明确名称；身份无法判断时标明待确认。
6. 具体角色姓名、作品名和专属身份标识由后续人物设定提供；保留与构图有关的发型体量、服装轮廓及道具占位等可见特征。用户明确要求替换人物时，身份识别特征按新人物调整。先核对跨格重复出现的发型、头带、服装与道具等线索，再判断是否同一角色；身份、性别、人数或动作关系无法确定时标明待确认，保留可观察的站位、姿势和轮廓，避免把猜测写成既定事件。
7. 原图对白用于识别字区大小、位置、形状与先后关系。本次在字区的画面描述中解释其任务，准确字样留给后续内容提示词或台词字段填写。
8. 黑白参考图默认提供分格与构图依据；成图色彩沿用用户指定的风格，风格缺省时采用彩色漫画。采用彩色时，将原图明暗块转换为相应的色彩、光照与对比关系；只有明确要求保留黑白技法时，才把灰阶网点或纯黑白处理写成整体画风要求。

三、画布与尺寸

优先采用用户指定的目标画布；尺寸缺省时，尽量保持参考图的宽高比，选择宽高均为 16 倍数的合适尺寸。

canvas 格式：
{"width":宽度,"height":高度}

宽高范围为 64～8192。先将参考图的全部区域按目标画布映射，再计算中心坐标。目标比例与原图不同时，优先通过留白、格间距和背景范围适配，保留主要构图关系。

说明中区分“版式画布”和“生成分辨率”。节点能输出 width／height，实际采样工作流需要把这两个输出接到潜空间宽高输入。

四、共用画面描述

根字段 description：整页画面描述，概括版式结构、主要视觉重心、整体风格及共用环境／光照。

每格 slotNotes：各框的画面描述，键与本格 slots 中的实际键一一对应。

- F：描述整格的景别、机位、叙事任务和主要内容关系。
- C：描述环境与背景的可见范围。
- S、L、R：描述角色编号、主体数量、占位、姿态、裁切、视线和遮挡关系。人物朝向明确使用“画面左／右”；解剖学左／右用于区分人物自己的手脚。
- O：描述局部、道具或声源的位置与可见范围。
- 各字区：描述对白／旁白／拟声的用途、说话人位置与在本格中的阅读先后。

画面描述采用明确、可见的内容关系，避免只写“这里放人物”“这里写文字”这样的空泛占位。局部特写写清所属人物与可见身体部分；小格根据空间选择半身、脸部或局部。表情依据眼睑、瞳孔、眉形、嘴形与头部朝向等可见线索描述，情绪概括与这些线索一致；血点、伤口、接触及攻防动作仅在图像依据明确时写入。

取景写清上、下及侧边的实际裁切位置。参考图在大腿、裤腿或其他部位截断时，沿用该裁切，使用“头部至大腿可见”“裤腿延伸到页面底边并被截断”等描述。画外部分留给后续设定；避免以“全身”“画到靴子”等措辞补齐原图未显示的身体，导致主体缩小或构图改变。

新版节点的 LLM 说明与直接提示词模式共用这些画面描述：LLM 模式将其作为内容分配参考；直接模式可将已填描述编译成画面内容。描述本身与图上实际印字分别填写。

本次默认输出 promptMode 为 "llm"，作为可复用模板。整页只使用一个 description 字段；旧格式的 usage、promptCaption 两份描述无需另写。

五、分格与内框

每个分格包含：

- position：唯一稳定标识，例如 panel-1、panel-2。
- layer：整数遮挡层级，建议从 0 开始，数值越大越靠前。
- slots：外框与实际需要的内框坐标。
- slotNotes：对应各框的画面描述。
- shapes：矩形框可省略；参考图存在明显斜边或凸四边形框时，为对应 F 或内框填写四角坐标，见第十节。

常用类型：

F：分格外框，每格一个。
C：完整内区或环境区。
S：主体区域。
L／R：左侧、右侧人物区域。
O：局部、道具或音效区域。
T／B：顶部、底部文字区域。
TL／TR：左上、右上文字区域。
BL／BR：左下、右下文字区域。
ML／MR：左中、右中文字区。

只建立参考图实际需要的内框；静默格保留人物、环境或道具区域即可。后续 LLM 按实际需要选择现有内框，框的存在本身不表示一定生成对应人物、台词或气泡。

六、同类内框与复杂姿势辅助定位

同一格可建立多个同类内框，每个内框使用唯一完整键：

- S、S_2、S_3：同类主体区域。
- TL、TL_2、TL_3：同类左上文字区域。
- O、O_2：分别安排的局部／道具区域。

第一个使用基础键，之后从 _2 开始依次编号。完整键在本格 slots 内唯一；不同分格可以各自使用 S、S_2 等相同名称。

每个编号框分别填写自己的坐标、slotNotes 和可选 shapes。后续内容项的 slot 必须完整引用清单中的键，例如 "TL_2"。

槽位编号只区分区域，不表示人物数量、角色编号、阅读顺序或遮挡层级。人物身份和数量由实际内容说明决定；字区先后由其位置、阅读路径及说明决定。例如角色1可以在不同格使用 S 或 R，S_2 也可以承载黑猫1。

同一个人在同一格中的一次连续身体展示，通常使用一个主主体框。多个框分别负责这次展示的不同局部时，写清所属角色及衔接关系。

参考图明确采用同一角色的放大面部肖像与较小站姿等多尺度并置时，保留这种构图，可用 S、S_2 等独立区域表达。各处沿用同一角色编号，并写明“同一角色的独立面部特写／另一处站姿展示、不同尺度”。它们属于同一身份的两次画面呈现，不作为两个人，也不把放大面孔与较小站姿拼接成一具身体。示例：S 写“角色3的独立放大面部肖像”；S_2 写“角色3的另一处站姿展示，站姿自身从头部到页面底边保持连续”。

复杂姿势采用“一个完整主体框＋少量关键局部辅助框”定位。S（或对应 L／R、编号主体框）保留这一次身体展示的整体姿势，写清躯干朝向、肩胯关系、重心、四肢衔接与可见裁切。再按实际需要用 O、O_2、O_3 等现有内框定位抓握、屈膝、交叉、遮挡或强透视部位；普通关节沿用整体描述，辅助框数量以解决明确的空间歧义为准。

每个局部辅助框明确：所属角色编号、解剖学左／右及具体部位、画面位置与朝向、连接的邻近身体部分、接触对象和前后遮挡。涉及衣物时同时写明该部位的覆盖状态；抓握时写清哪只手抓住哪个角色或物件的哪一处。透视放大的手脚仍归属原角色，其尺度变化由机位解释。

主体框覆盖整体可见范围，局部框落在对应部位的实际区域，可与主体框合理重叠。辅助描述细化同一次展示中已有的部位，和主体描述中的左右、数量、动作、衣物与连接关系保持一致；各局部只写其负责范围。局部辅助框作为内容区域处理，保持为同一画格中的连续人物，而非新增分格或另一位完整人物。内框提供区域与语义引导，不等同于关节骨骼控制或硬性姿态约束。

后续 LLM 输出 summary／items 内容提示词时，明确承担实际定位任务的局部框分别生成引用对应完整 slot 的局部 item。主体 caption 提及该部位，只补充语义，不能替代局部 item 的区域定位；节点只为实际输出的 item 回填坐标。一次身体展示可由一个主要 character 项加多个局部项共同表达，item 数量不等于人物数量，人物局部也可使用 character 并明确归属。仅重复文字而没有独立定位作用的区域，才可合并或省略；空框仍按需省略，不填占位项。

例如抓袖跃起：S 写角色1的整体前倾、屈膝与跨格腿部；O 写角色1抬起的手抓住角色2袖口附近的衣袖，手腕连续连接角色1的前臂；O_2 写角色1屈膝腿的膝部、小腿与鞋的朝向。下格角色2的前景手部可另设本格的 O，写清其经手腕、袖口与前臂连接角色2自身的肩部。具体左右和角度依据参考图确定。

多个字区按实际阅读路径摆放，使各泡有清晰独立空间，并为脸部、关键手势及重要道具保留可见区域。

JSON 对象内使用不同键保存不同框；同名键重复出现会发生覆盖，无法表达两个独立区域。

七、跨格主体

逐格检查所有主体与 F 实际轮廓的关系，包括下格人物的头发、头部、手、衣袖、道具，以及上格伸下的腿和鞋。出框可以只进入格间留白，也可以延伸至相邻画格；局部出框与大范围跨格都按参考图记录。非矩形格以实际四边形边界为准，仍位于 F 外接矩形内的内容也可能已经越过斜边。

参考图中存在出框或跨格主体时：

1. 将主体归属到一个实际分格，例如 panel-2 的 S。
2. 将该 S 的坐标扩展到人物在整页实际占据的范围，允许超出所属 F，整体仍位于画布内。
3. 在该 S 的 slotNotes 中写清：这一次身体展示自身连续、从哪里延伸到哪里、越过哪些格线、位于哪些背景前方，以及需要避让的脸部／字区／局部。“连续身体”只约束这一处展示内部的衔接；同一角色另有独立放大肖像时，按第六节说明两处展示的关系。
4. 在被跨越画格的 F／C 描述中说明其背景与前景人物的关系。
5. 出框或跨格人物沿同一轮廓连续呈现；实际格数仍按独立画格统计。
6. 为每处越界写清所属角色、部位、越过哪条实际边界、伸向哪里、位于格线及邻近内容的前方还是后方，并为需要保留的脸部、字区和关键动作留出空间。参考图有意遮挡时保留遮挡关系，其他区域按实际位置分开安排。主体／局部框坐标覆盖对应的出框部分，描述与几何相互对应。

采用可编辑的 S 或编号主体框表达跨格构图，本次无需添加 X 框。模板里每个跨格框的作用都落实到实际坐标和描述。

同一角色在其他独立分格中的再次出场，按相应叙事时刻分别安排；它与同一格中误复制完整人物属于不同情况。

局部出框示例：下格角色2的头发越过下格上边界，进入白色格间距并位于该处格线前方；其头、颈、肩仍属于下格同一次连续展示。对应主体框覆盖越界的发梢，在本格 F／S 描述中同时写明。上格角色1伸下的鞋另行定位，两者是否遮挡按参考图交代。该例只演示记录方法，实际模板依据各自参考图安排。

八、读序和遮挡层级

panels 数组的排列顺序就是格号与实际读序：第一个条目是 panel 1，第二个条目是 panel 2，以此类推。

按照参考图的叙事和对白顺序排列数组，readingOrder 用文字明确写出同一顺序。readingOrder 是说明字段，节点实际读序由 panels 数组落实；改变读序时同步调整数组。缺乏可靠阅读线索时，采用上到下、同行左到右，并在 readingOrder 中保持一致。

layer 单独表示前后层级，较大的层级位于较小的层级前方。改变前后层级不改变 panels 的阅读顺序。内框随所属分格保存，不单独设置 layer。

当前节点的自动遮挡说明按 F 外框的矩形范围是否重叠来生成；非矩形框的重叠判断也是外接矩形近似。若仅 S 跨出外框而两格 F 没有重叠，需要在相关 slotNotes 中写清主体与背景的具体前后关系。

层级、四边形轮廓和跨格关系最终作为提示词布局条件传给 MOSS，属于语义引导，不是逐层合成或强制裁切蒙版。

九、中心像素坐标

slots 中每个框使用整数像素数组：
[top, left, bottom, right]

原点为整张目标画布中心。设目标尺寸为 width × height，区域在左上角原点坐标系下为 x1、y1、x2、y2，则：

top    = y1 - height / 2
left   = x1 - width / 2
bottom = y2 - height / 2
right  = x2 - width / 2

约束：

- top < bottom，left < right。
- -height / 2 ≤ top < bottom ≤ height / 2。
- -width / 2 ≤ left < right ≤ width / 2。
- 每个内框有实际面积，边界与参考图中的对应区域匹配。
- 内框可以超出所属 F，但各坐标仍落在整张画布范围内。

版式几何使用 slots，非矩形轮廓另用 shapes；bbox、bbox_coord_space、bbox_format 属于节点后续编译的生图内容格式，无需在版式根对象另写。

十、斜框与非矩形轮廓

1. 何时填写 shapes

参考图存在明显倾斜边界、梯形或其他凸四边形分格时，为该格填写 shapes.F，保留边线的实际倾斜方向和相对幅度。只在文字中写“斜框”而仅填写矩形 slots.F，不能表达其实际几何。矩形框直接使用 slots 即可；参考图中笔触造成的轻微抖动可归纳为直边。

2. 四角坐标与外接矩形

先在参考图上定位四个实际角点，映射到目标画布，再转换成中心像素坐标。从视觉左上角开始，按左上、右上、右下、左下的顺时针顺序填写，每点为 [x,y]。强倾斜四边形以保持轮廓顺时针、四边互不交叉为准。

slots 使用 [top,left,bottom,right]，shapes 使用四组 [x,y]，两种顺序分别填写。每个带 shapes 的框，slots 保存由同一组角点计算出的最小外接矩形：
[min(y1,y2,y3,y4), min(x1,x2,x3,x4), max(y1,y2,y3,y4), max(x1,x2,x3,x4)]

下面是一个分格条目的几何片段，假定画布为 1024×1536，展示上边水平、下边向右上方倾斜的 F 外框；并非完整可导入的根对象：

{
  "position": "panel-1",
  "layer": 0,
  "slots": {
    "F": [-600, -440, -160, 440]
  },
  "shapes": {
    "F": [[-440, -600], [440, -600], [440, -240], [-440, -160]]
  },
  "slotNotes": {
    "F": "上边水平、下边从画面左侧向右侧抬高的四边形画格，按所列四角保留实际外框。"
  }
}

shapes 的键必须与本格 slots 中的实际键一致。四点形成有效凸四边形，面积大于零，边线互不交叉，角点互不重合，全部位于画布内。推荐将映射后的角点取整，再由这些点统一计算外接矩形。

另做一次斜边方向核对：画布 x 向右增大、y 向下增大，转换到中心原点后方向仍相同。对上端 A 与下端 B，xB > xA 表示从上往下向右偏，xB < xA 表示向左偏；对左端 A 与右端 B，yB < yA 表示从左往右抬高，yB > yA 表示向右降低。逐边对照参考图，确保实际坐标、slotNotes 的方向描述和参考图一致。四点顺时针或 JSON 校验通过，只证明基本几何有效，不能证明斜线方向还原正确。

3. 相邻斜框与格间留白

相邻格分别沿参考图的实际边界定位，保留两条边界之间的白色格间距。参考图中的上下两条斜边分别保存为两格的边界；白色间隔仍是格间留白。

成组核对相邻边界：中央分隔斜线、上排各格的斜底边、下一排的斜顶边，以及它们相接处的间隔，分别根据参考图填写。原图两条边之间存在白色分隔带时，各自描出分隔带的一侧；避免让两格共用完全相同的边线，或只还原中央斜线却把其余明显斜边改成水平。检查留白是否在端点塌缩为零，或因端点不一致产生意外楔形；原图本来存在渐变宽度时保留该变化。

检查实际四边形是否相交，以及格间留白在各处是否仍有有效宽度。参考图是普通相邻分格时，保持轮廓分离；参考图存在嵌入或覆盖时，保留真实重叠并按 layer 说明前后关系。宽度不同或不平行的斜边按参考图保留，无需强制变成等宽间隙。

外接矩形相交不等于真实斜框相交。当前节点仍用 F 的外接矩形近似生成自动遮挡说明，可能把实际分离的斜框标记为重叠。遇到这种情况，交付说明列出涉及的格号、真实轮廓关系和外接矩形判断的局限；slotNotes 写清真实间隔。保留参考图几何，单靠文字或调整 layer 不能保证消除编译器的近似遮挡提示。

4. 斜框内的主体和字区

根据四边形实际可见空间安排 C、S 和字区。shapes.F 只表达外框轮廓，不能据此假定所有内框自动贴合斜边。需要倾斜的内框分别填写对应 shapes，例如 shapes.S 或 shapes.TR；适合矩形的内框可以保持矩形，并放入有效空间。

普通内容区尽量位于实际轮廓内；参考图存在跨格主体或气泡时，按其实际范围扩展，并写清归属和前后关系。四角点描述的是区域几何；圆形、椭圆或不规则气泡的具体容器形状，另外写在字区描述中。

复杂曲线、凹多边形或超过四个顶点的框，使用合理凸四边形近似，并在描述与交付说明中交代轮廓差异。节点的几何与描述用于引导 MOSS，实际成图仍需检查边界还原情况。

十二、交付前检查

1. 输出可以由标准 JSON 解析器直接解析，字符串内换行使用合法转义。
2. 根对象使用 panels，并包含至少一个实际分格；画布宽高在范围内且为 16 倍数。
3. panels 条目数量等于参考图实际独立画格数，格内小元素和无独立外框的跨格人物均按内容处理。
4. 各 position 唯一，panels 数组顺序与 readingOrder 一致；layer 独立表达前后关系。
5. 每格有一个 F；其他内框根据实际需求建立。
6. 同类重复内框使用唯一编号，各框的坐标、描述、轮廓独立；同一完整键只出现一次。
7. slotNotes 和 shapes 的键都能在本格 slots 中找到，所有框及角点位于画布内。
8. 坐标采用中心像素 yxyx，shapes 角点采用中心像素 xy，非矩形 slots 是对应轮廓的外接矩形。
9. 已逐格核对主体与实际 F 轮廓的关系，头发、头部、手、衣袖、鞋和道具的局部出框均有记录；出框／跨格部分的坐标、连续轮廓、覆盖范围及前后关系与参考图一致。
10. 字区符合人物位置和阅读路径，静默区域保留实际画面空间；通用模板通过画面描述解释文字用途。
11. description 是共用整页描述，slotNotes 是各框共用描述；具体人物身份与准确台词留给后续内容阶段。
12. 参考图的明显斜框均有对应 shapes.F；逐边核对倾斜方向与幅度，并成组核对相邻格的斜底边、斜顶边及分隔带。四角绕序、外接矩形、端点与格间留白一致，真实遮挡与外接矩形近似判断分别说明。
13. 同一角色跨格沿用同一角色编号；角色编号、槽位编号和左右位置分别表达。人物朝向、表情、衣物轮廓、动物与手部关系均有图像依据，无法判断处在交付说明中标明。
14. 同一角色的独立放大肖像与站姿已区分为两处不同尺度展示，各处身份一致；身体连续性只约束各自内部，保留参考图有意的重复呈现。
15. 实际可见范围与参考图一致，页面边缘的裁切位置已经写清；角色人数、身份、画外身体和战斗动作均依据可见线索与用户要求处理。
16. 复杂姿势的关键空间歧义由主体框与必要的局部辅助框共同说明；局部角色归属、左右、数量、衣物、连接和接触关系与整体描述一致，各框细化已有部位。后续内容整理保留有独立定位作用的局部 item，只有描述重复且无独立区域任务时才合并。

交付说明区分内容检查与几何检查。本次反推版式须核对实际生成的 canvas、slots 与 shapes，再报告具体结果；后续只有槽位清单与文字描述的内容整理阶段，可以检查描述矛盾，但应注明尚未核对完整几何。以实际获得的数据为依据，不能仅凭槽位名称或文字坐标片段断言“没有几何冲突”。

随后输出简短说明和一个标记为 json 的可复制代码块，代码块内放完整单页 JSON 对象。说明放在代码块外，JSON 内保持标准语法。该对象保存为 UTF-8 .json 文件后，可从节点的“导入”按钮加入共用版式库；后续使用“编辑版式”继续调整。
