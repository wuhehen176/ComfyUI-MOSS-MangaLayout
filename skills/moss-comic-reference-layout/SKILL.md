# MOSS 漫画参考图反推（通用版）

把参考图转成用户能在 `ComfyUI-MOSS-MangaLayout` 中选择、编辑和复用的版式。交付版式 JSON、带快照的节点工作流及内容提示词；用户要求实际测试时，再用其已有 MOSS 工作流采样并检查真实图片。

本流程不依赖特定 agent 工具名或电脑。使用当前环境可用的看图、文件、Python 和 HTTP 工具；环境适配见 [references/comfyui-adapter.md](references/comfyui-adapter.md)。缺少节点或运行工具时可交付未编译草稿，明确哪些步骤尚未验证。不要虚构工具调用或生成结果。

## 确定参考图负责什么

- 区分版式、镜头、动作、身份、服装、画风和文字参考。人物替换只改变指定身份与相应识别特征，尽量保留叙事功能、姿态和人物占位。
- 用户明确指定的参考职责优先。未指定时沿用参考图的色彩媒介；如要求彩色改编，应同步处理全局、局部、背景、配角和负面词。黑白参考也可只负责版式，不能与用户的彩色要求混淆。
- 无法辨认的对白不猜作原文。用户要新示例时可自拟简短连续对白，并说明它是示例；只要求忠实提取时，把未知字样列为待补，不生成空 text 项或杜撰原台词。
- 常规几何与镜头选择直接按图推进；只在缺少必要参考图、目标身份无法判断或现有工作流无法定位时澄清。

## 分清画框和元素

先记录实际背景格、读序、框间间隔和遮挡，再记录格内主体、文字、局部及跨格人物。

- 同一格的脸、手、气泡和背景不重复计格。跨格大人物没有独立外框时，不自动增加一格。
- 整页前景人物可归属一个实际格，把其 `S` 内容槽扩展到所需范围；caption 明确“同一连续身体、无独立矩形框、覆盖背景格线”。不要为它伪造透明第五格。见 [references/node-contract.md](references/node-contract.md)。
- 读序与遮挡 `layer` 分开处理，层级不改变事件先后。先后动作使用独立格；同一时刻的局部补充才采用嵌入结构。
- 机位、裁切与复杂度适应格子。手部特写只写所属人物当前可见的手与对象，不补整套身体；小格通常适合半身、脸或局部。用户要求保留全身时，为其分配足够空间，不把个人的小格限制推广为所有任务的硬规则。
- 尽量遵循参考图宽高比；沿用用户既有尺寸时说明比例适配。尺寸兼容性以实际潜空间节点为准，不把某一工作流的倍数要求推广到所有节点。

## 分别落地版式、用途、内容

读取 [references/node-contract.md](references/node-contract.md) 后生成文件。

1. **版式**：`canvas`、有序 `panels`、实际 `slots`、可选 `shapes` 与 `layer`。坐标为中心像素，外接框为 `yxyx`，四角点为顺时针 `xy`。
2. **用途**：每格 `slotNotes` 写明 F 的叙事任务，以及实际主体、局部、道具和字区的用途。跨格 S 写清归属、越界范围、连续身体、遮挡与避让。两种模式共用画面描述：LLM 模式用它指导外部模型分配内容，直接模式可把已填描述编译为画面内容；描述本身不是图上印字。
3. **内容**：根对象含 `summary`、`items`，可附 `layout`；item 用整数 `panel` 和实际存在的 `slot`。MOSS 描述推荐英文 caption；对白、拟声的语言与字体按用户要求或参考图确定。未指定时保留能辨认的原文，不默认把所有任务译为中文或日文。

替换人物先核对身份标签与稳定外貌。已知示例是 `arona (blue archive)`、`asuma toki (blue archive)`，不能据此猜造其他标签。角色库、已确认资料或可靠角色参考中的发色、瞳色、饰品优先，不从参考原人物继承这些身份特征。外搭服装可按用户要求保留；原人物的脸部饰品不自动变成新角色固定设定。

跨格重复少量可见身份锚点，神态随事件更新。同一角色在别格再次出现是正常叙事重复，不用全局“禁止重复人物”压掉它；仅防止同一时刻误复制身体或道具。

对白按所选读序连贯分配，一句一泡；长句可在语义边界拆成不重复的两泡。气泡靠说话人或画外声源，避脸与关键手势，沉默者不补空气泡。字号根据文字长度、语言与实际字区容量选择；用户提供阈值时沿用，不把案例的字号规则推广到所有语言。容量不足换字区、版式或分页，不继续缩字硬塞。拟声字号按声源与可读性选择。

## 编译与保存

- 使用节点现有 Python 编译器，不再重写一份。可用 `scripts/compile_template.py`，参数见 `--help`。
- 检查实际格数、panel/slot、读序、容量与遮挡。数字 ID 和 items 数量均不代表格数。
- 工作流保存完整版式快照，旧工作流不随公共库修改。节点选择优先；不偷偷删人物或对白来通过校验。
- 用户要求加入库时，先备份，再用 revision 检查新增或更新指定 ID，保留其他条目；修改既有 ID 前确认是用户指定的那套。不能从“添加模板”推断清库权限。
- 更新发行包示例或初始库时，不覆盖正在使用的共享库；已有库清空后不自动恢复初始模板。

## 仅在用户要求时实际试跑

读取 [references/comfyui-adapter.md](references/comfyui-adapter.md)，获取使用者提供的环境信息，检查指定服务、队列与当前工作流。不要猜测固定端口、磁盘路径、模型或节点 ID。

- 将真实 `MossMangaLayout` 输出接入正向文本与宽高。只能离线编译时明确说明，不能把 JSON 校验称为生图测试。
- 复用用户模型、编码器、VAE 与采样分支。只在本次请求清理明确冲突的提示词和不适用 LoRA，记录差异，不改保存的原工作流。
- 更换题材时检查负面词是否压掉所需的彩色／黑白、跨格重复出场或多人场景，不套固定词表。
- 正常排队，不取消其他任务；保存 prompt ID、请求和 history。中断后按已保存 ID 查状态，避免重复提交。
- 默认只跑用户要求的一张。执行失败可定位修复；技术成功但画面不够准时，先展示实际结果和差异，不自动进行无上限多轮抽卡。

## 验收交付

查看实际图片，分别核对格数与边界、跨格身体连续性、人物身份颜色、局部归属、姿态、文字完整性读序、气泡归属和背景颜色。执行 success 只证明运行成功。

交付可点击的版式、节点工作流和实际图；说明库中名称与刷新方式。指出“底部格扩宽”“披风变短”等实际差异，不承诺像素级裁切。用途里的目标不能当作验证结果。
